three endpoints. that is the whole API.
POST /experiments — create an experiment with variants
GET /experiments/:id/assign?user_id=xyz — assign a user, get their variant back
POST /experiments/:id/event — log a conversion
GET /experiments/:id/results — see which variant is winning
how it works
01

Create an experiment

Send a POST with a name and a list of variants. Get back an experiment ID. That is it.

02

Assign users

Call /assign with any user ID. TesiT hashes the ID to a variant — same user always gets the same result.

03

Log conversions

When something meaningful happens, call /event. TesiT ties the event back to the assigned variant automatically.

stable assignment

Same user. Same variant. Every time.

Assignments are hash-based, not random. No session storage, no cookies required. A user_id always maps to the same variant for the lifetime of the experiment.
